# Итоги работы за 7 октября 2026

## Выполнено

- Перестроена модель устранения нарушений: каждое мероприятие содержит своё подразделение, объект, ответственного, срок и статус.
- Реестры проверок и нарушений дополнены нужными данными: сроками, ответственными с должностями, объектами, подразделениями и видами проверки. Строки нарушений открывают карточку с деталями мероприятий.
- Устранено падение страницы при повторном переходе в раздел нарушений; сохранение изменений проверки проверено через API.
- Убраны устаревшие «Области проверки».
- Настроены правила для видов контроля:
  - для ПК III вид проверки обязателен, а объект и подразделение нужны только для плановой и внеплановой проверки;
  - для ПК II, Ростехнадзора и Газнадзора вид проверки, объект и подразделение не используются.
- Добавлена миграция, позволяющая не указывать вид проверки там, где он не применяется.
- Создан модуль импорта нарушений из `.xlsx`, `.xls` и `.docx`:
  - загрузка файла и предпросмотр;
  - серверная проверка строк;
  - подтверждение с одной транзакцией: все записи создаются либо откатываются целиком;
  - журналирование импортированных нарушений и мероприятий.
- Для загруженного Word-файла «Акт-предписание…» настроен автоматический разбор: служебная строка нумерации пропускается, колонки распознаются, срок извлекается из текста мероприятия. Предпросмотр через интерфейс показал 8 корректных строк без ошибок.
- Синхронизирована локальная учётная запись администратора с настройками разработки и проверен вход через интерфейс.
- По решению пользователя доработки импорта отложены на поздний этап; приоритет отдан следующему разделу архитектуры.
- Реализован раздел «Контроль сроков»: серверная сводка (всего мер, просрочено, срок ≤ 7 дней, не устранено, устранено, устранено с просрочкой), фильтры по статусу и подразделению, список мер с переходом в карточку нарушения.
- Карточка нарушения дополнена действиями по срокам: перенос срока с причиной и историей изменений; фиксация устранения с датой и отметкой «в ходе проверки»; автоматическое определение «устранено с просрочкой» и числа дней просрочки на момент устранения.
- Для ПК II сроковые поля скрыты во всех формах и карточке; меры ПК II исключены из списка контроля сроков.
- Исправлены краевые поведения формы проверки: вид проверки не отображается без выбранного вида контроля; при смене вида контроля сбрасываются неприменимые поля (вид проверки, подразделение, объект).

## Проверено

- Backend: `pytest` — 26 тестов успешно (включая расчёт сроков: дни просрочки, остаток дней, окно «срок ≤ 7 дней»).
- Frontend: `npm run build` — сборка успешна.
- Импорт Word-документа: предпросмотр через интерфейс; полный цикл подтверждения проверен на временной тестовой проверке, тестовые записи удалены.
- Контроль сроков проверен в интерфейсе: перенос срока с историей, устранение в ходе проверки, ограничения ПК II, пересчёт сводки после изменений.

## Осталось по архитектуре

1. Доработки импорта отложены на поздний этап (см. D-015): интерактивное сопоставление колонок, выбор таблицы Word и строки начала данных, расширенные тесты импорта.
2. Заявки на перенос срока отложены (см. D-016): перенос выполняет Специалист или Администратор напрямую, изменение сохраняется в истории сроков.
3. Реализовать следующие прикладные разделы архитектуры: аналитика, оценка эффективности ПК, отчёты и экспорт, история изменений.
4. Расширить автотесты: проверки ролей, транзакционный откат импорта, интерфейсные сценарии.
5. Зафиксировать завершённые этапы (импорт, контроль сроков) итоговой проверкой и коммитом.
