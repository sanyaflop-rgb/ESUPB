# Архитектура PK CONTROL

## Контекст

PK CONTROL — LAN-приложение для учёта и анализа нарушений по контурам ПК III, ПК II, Ростехнадзор и Газнадзор. Пользователи открывают систему в Edge/Chrome без установки клиентского ПО.

```text
Браузер → React (статические файлы) → FastAPI API → SQLite на диске сервера
                                               ↘ сетевой каталог документов/резервных копий
```

## Технологии

- Backend: Python, FastAPI, Pydantic Settings, SQLAlchemy 2, Alembic.
- Frontend: React, TypeScript, Vite.
- База MVP: SQLite на локальном диске хоста.
- Целевая совместимость: PostgreSQL без изменения предметной модели.

## Инварианты

1. Backend — единственный источник бизнес-логики и авторизации; frontend не дублирует расчёты.
2. Файл SQLite запрещено размещать на SMB/сетевой папке. Только серверный процесс обращается к БД.
3. Сетевые каталоги хранят вложения и резервные копии. В БД — метаданные, хеш и относительный путь.
4. Справочники деактивируются; нарушения аннулируются, а не удаляются.
5. Изменения сроков, классификации и критичных полей попадают в аудит.
6. SQLAlchemy-модели и миграции не используют SQLite-специфичный SQL.

## Границы этапа 1

Созданы запускаемые базовые приложения и конфигурация миграций. Предметные таблицы, авторизация, статическая раздача frontend и файловое хранилище будут добавлены следующими этапами.
