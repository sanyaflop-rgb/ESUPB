# Модель данных

На этапе 1 предметные таблицы ещё не создаются; Alembic настроен и готов к первой миграции.

Планируемые ключевые сущности:

- пользователи, роли и назначения;
- подразделения, объекты, лица;
- виды контроля, виды проверок;
- проверки и области проверки;
- группы и типы нарушений, нарушения;
- ответственные подразделения и лица;
- вложения, переносы сроков, связи повторности, аудит;
- оценки эффективности, вводимые факты и результаты.

Ключевые связи: `проверка → области проверки → нарушения`. Целевая проверка может включать несколько сочетаний «подразделение + объект».

Все идентификаторы будут внутренними UUID/целочисленными ключами; номер документа хранится отдельно вместе с нормализованным ключом, уникальным в паре с видом контроля.
